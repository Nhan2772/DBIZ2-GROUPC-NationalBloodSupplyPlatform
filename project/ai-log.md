A correction recorded here does **not** change a requirement or approve a design by itself: the owning W0/W1/AD/SD/Screen Spec/UI Convention must be updated and reviewed separately.

## Evidence and review status

- **Historical source:** the team's DBIZ2 conversation reviews and explicit correction requests. These discussions are **not presently stored as a versioned transcript in this repository**. The entries document what was challenged and the team's stated correction, not a claim that Git commit history independently proves every AI suggestion.
- **Repository cross-check:** the referenced W0, AD/SD, Screen List, Screen Specs, UI Conventions and README were reviewed against the GitHub `main` branch on **22 November 2026**. A linked document being present is **not** proof that its Mermaid renders, every PNG matches its numbered elements, or every open question is closed.
- **Authority:** this log is a **history of AI feedback**, not an approved decision record. Where a row and an owning file disagree, preserve the discrepancy and request a team decision; do not silently edit the owning document.
- **What is intentionally omitted:** speculative AI mistakes, generic warnings, and proposed changes for which no team rejection/correction is documented. Missing repository files and unrelated consistency findings belong in a repository audit or the owning document's Open Questions instead.

## How to append a new entry

Copy the five-column row format above. Include the **lesson**, a precise account of the **AI proposal**, the **NBSP-specific reason for rejection**, and **what the team actually did** with a working source link or an explicit `Not yet recorded in repository` note. Do not alter a previous row to make an old decision appear newer; append a new row and reference the superseded item.
